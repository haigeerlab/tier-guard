## 方法

隔离脚手架，`claude -p --plugin-dir <探针插件>` **只为单次会话**加载，
**不修改 `~/.claude/settings.json`**。探针记录 `PreToolUse` / `SubagentStart` /
`SubagentStop` 的完整 payload。

> **探针自己先出了一次 bug**：第一版用 `python3 - <<'PY'` 读 payload，
> 而 heredoc 会占用 stdin，`sys.stdin.read()` 拿到空字符串——
> 三个事件都触发了，但 payload 全是 `_unparsed: ""`。
> 实跑时当场发现并修复，随后给探针补了一正一反自检
> （喂 `tool_name:Agent` 必须吐 `updatedInput`；喂 `tool_name:Bash` 必须不吐）。
>
> 这正是「新写的检查器默认是坏的，直到你用真实数据跑过一遍」。
> 如果只看「三个 hook 都触发了」就收工，会得出「payload 是空的」这个错误结论。

## 结论

| # | 问题 | 结论 |
|---|---|---|
| ① | `PreToolUse` 的 matcher 对派子代理的工具是否生效？工具名是什么？ | **通过**，工具名 = `Agent` |
| ② | `updatedInput.model` 是否真作用到被 spawn 的子代理？ | **通过** |
| ③ | **插件形态**能否注册 `PreToolUse`？ | **通过** |
| ④ | Codex 桌面版跑不跑 hook？ | **没跑起来** |
| ⑤ | Codex `spawn_agent` 的 model / reasoning_effort 覆盖？ | **exec 模式下不适用** |

### ① 工具名是 `Agent`

`PreToolUse` payload 实测：

```
tool_name  = "Agent"
tool_input = {description, prompt, subagent_type, run_in_background}
其余字段    = session_id / cwd / prompt_id / permission_mode /
             effort / hook_event_name / tool_use_id / transcript_path
```

matcher 写 `"Agent"` 命中，写 `"Bash"` 不命中（探针自检的反向用例）。

### ② `updatedInput.model` 生效——差分证据

两次运行**只差一件事**：hook 有没有改写 `model`。

| | 子代理实际跑在 |
|---|---|
| 对照组（不改写） | `claude-sonnet-5`（继承主会话） |
| 处理组（改写为 `haiku`） | `claude-haiku-4-5-20251001` |

主会话两次都是 `sonnet`，且 prompt 明确要求模型**不要传 `model` 参数**——
模型确实没传，档位完全是 hook 单方面钉进去的。

**证据来源是子代理自己的 transcript**（路径由 `SubagentStop` payload 的
`agent_transcript_path` 给出），不是听模型自述跑在哪个模型上。

**这条通过意味着 `auto` 模式成立。** 不通过的话整个方案只能退回
「建议 + 模型自觉」，也就是参考方案 `codex-auto-model-router` 那种形态。

### ③ 插件形态可注册 PreToolUse

`--plugin-dir` 加载的插件，其 `hooks/hooks.json` 里注册的
`PreToolUse` / `SubagentStart` / `SubagentStop` **三个事件全部触发**。

这条决定了**交付形态必须是插件，不能是往 `~/.claude/settings.json` 塞 hook 片段**：
Claude Code 官方文档明确 Cloud 会话「don't read your local `~/.claude/settings.json`;
hooks there come from the repo and from your organization's server-managed settings」——
**插件 hook 在 Cloud 上照常生效，settings 片段不生效**。

### ④ Codex 桌面版：没跑起来（不是不通过）

Codex 的 hook 需要**在新会话用 `/hooks` 人工审核并信任**，是交互式步骤，
自动化不了。

已知的间接证据：桌面版内嵌的二进制与 CLI 同为 `codex-cli 0.153.4`，
`PreToolUse`(38) / `PostToolUse`(33) / `updatedInput`(6) /
`hookSpecificOutput`(8) / `hooks.json`(7) 计数逐项相同。
**桌面版不是另一套实现，是同一个引擎换了个壳**——所以风险低，但
「同一个二进制」不等于「桌面壳把配置和信任流程接上了」，仍需人工验一次。

**后续证据更新（2026-09-12）**：桌面命令菜单未列出 `/hooks`。这只证明该命令未出现在菜单，
不能推出桌面不支持 hook；此前经协作代理 API 的派活也不进入 `PreToolUse`，因此桌面结论仍待
原生 hook 事件证据。

### ⑤ `codex exec` 不暴露 `spawn_agent`——差分证据

| 配置 | 工具清单里有 `spawn_agent` 吗 |
|---|---|
| 隔离 `CODEX_HOME`（`multi_agent = true` + `expose_spawn_agent_model_overrides = true`） | **没有** |
| 真实 `CODEX_HOME` | **没有** |

两边都没有 → 不是配置写错，是 **`codex exec`（非交互）本身不暴露多 agent 工具**。

这条把 Codex 侧劈成两条阻塞状态完全不同的链路，见 [`../../tasks/tier-guard/plan.md`](../../tasks/tier-guard/plan.md) 的 Task 4a / 4b。

## 附带发现（都进了设计）

1. **`SubagentStop` payload 自带 `agent_transcript_path` 和 `last_assistant_message`。**
   SPEC 的 Open Question 1（「升级触发次数怎么统计」）因此**解决**——
   有一手数据源，不必事后扫 transcript。
2. **`PreToolUse` payload 带会话级 `effort: {level: "high"}`**，可作为路由输入。
3. **Codex 的 `updatedInput` 必须与 `permissionDecision: "allow"` 同时出现**
   （否则报 `PreToolUse hook returned updatedInput without permissionDecision:allow`），
   Claude 侧无此约束。**两个宿主的薄壳不能共用同一段输出代码**——
   判据可以共用，输出编码不行。

## 一条被推翻的既有说法

参考方案 `orange-the-weak/codex-auto-model-router` 的 Luna / Terra / Sol 分工
（Luna=机械基线 / Terra=延迟优先 / Sol=复杂顶档）**与 OpenAI 自己的模型元数据对不上**。

`~/.codex/models_cache.json`（`fetched_at: 2026-09-11T14:49:08Z`，由本机 CLI 0.153.4 自己缓存）：

| slug | priority | 官方 description | default effort |
|---|---|---|---|
| `gpt-6-astra` | 1 | Our most capable model for complex, demanding work | medium |
| `gpt-5.6-sol` | 6 | Reliable agentic workhorse for everyday tasks | low |
| `gpt-5.6-terra` | 7 | Balanced agentic coding model for everyday work | medium |
| `gpt-5.6-luna` | 8 | Fast and affordable agentic coding model | medium |

「Terra = 延迟优先」没有任何一手依据；真正「快而便宜」的是 Luna。
且 `priority` 排序（sol > terra > luna）与 description（sol 是 "workhorse"、
terra 是 "balanced"）**互相不支持**，读不出 sol 和 terra 的强弱。

> 说明：参考仓那段结论是经由网页抓取 + 小模型转述得到的，
> 可能是转述失真而非原文有错。但无论哪种，**都不该拿它当映射依据**——
> 一手数据就在本机。

**设计后果**：tier 映射的自动升档**只踩 `effort` 这根杠杆**
（`low < medium < high < xhigh < max < ultra` 是 OpenAI 自己定义的单调序列），
不赌三个 5.6 slug 的相对排序。见 SPEC 的分级判据表。
